# pose_net.sim_pretrained.pt — provenance and honest status

**Do not copy this to `pose_net.pt` (the production filename) without reading this.**

## What it is

A `PoseNetV2` checkpoint pretrained on **simulated** CSI, generated by:

1. Downloading real human motion capture data (38 subjects, ~54 trials) from
   the [CMU Graphics Lab Motion Capture Database](http://mocap.cs.cmu.edu/)
   (via the `una-dinosauria/cmu-mocap` BVH mirror).
2. Running forward kinematics on each BVH file to get real 3D body-joint
   trajectories, rescaled to human proportions and placed in a simulated
   5×5×3m room matching EchoPose's 3-node layout.
3. Simulating the WiFi channel response with a simplified multipath
   scattering model: a fixed per-room static-reflection baseline plus a
   moving point-scatterer contribution per body segment (13 scatterers —
   head, shoulders, elbows, wrists, hips, knees, ankles), evaluated across
   64 OFDM subcarriers at 5.8GHz.
4. Training `PoseNetV2` on the resulting (simulated CSI, real pose) pairs.

This is meaningfully different from (and better-founded than) training on
random noise or on a foreign dataset's CSI: there is a genuine, deterministic
relationship between body pose and the simulated CSI by construction, driven
by real human motion. Full build scripts (`bvh.py`, `csi_sim.py`,
`build_sim_dataset.py`) were used in a scratch directory outside this repo;
ask if you want them added to `scripts/`.

## Honest evaluation result (leave-one-subject-out, 38 folds)

| | Mean MPJPE | PCK@10cm |
|---|---|---|
| Zero baseline (predict average pose) | 91.0 cm | 0.29% |
| This checkpoint (per-fold retrain) | 88.2 cm | 0.52% |

Trained model beat the baseline on 24/38 folds (63%). That is a real but
**weak** signal — the mean improvement (2.8cm) is small relative to the
per-fold standard deviation (~40cm). Likely limited by: still-small dataset
(1801 windows), a simplified (non-ray-traced) propagation model, and possibly
an under-tuned scatterer reflectivity constant.

## What this checkpoint is / is not for

- **Is**: a legitimate starting point for `pipeline/fast_adapt.py` (LoRA
  fine-tuning) once you have even a modest amount of real ESP32 CSI + real
  pose data — pretraining on physically-motivated simulated data before
  fine-tuning on real data is a standard technique to reduce how much real
  data is needed.
- **Is not**: validated on real hardware. Its real-world PCK on your ESP32
  nodes is unknown and could be anywhere from "helpful head start" to "no
  better than random" — there is no way to know without real data.
- **Never** rename this to `pose_net.pt` and deploy it as if it were a
  finished, accurate model. `pose.py`'s production guard checks for the
  *presence* of `pose_net.pt`, not whether it's actually accurate — it would
  silently pass the same "not simulation mode" check the noise-trained
  checkpoint incorrectly passed before.
